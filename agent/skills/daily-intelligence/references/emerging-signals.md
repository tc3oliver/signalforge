# Emerging Signals — 沒有任何一則 item 說出口的事

## 定義

emerging signal 是**跨多則不相關來源的重複底層主題**,而且沒有任何單一 item
把它當成主旨。如果有一篇文章標題就寫著「XX 正在成為趨勢」,那是一則 story,
不是 signal — 它已經被說出來了。

signal 的價值在於:讀者看了五則個別的 story 不會想到它們有關,
你把它們並排,關聯就浮現。

---

## 怎麼找

### 1. 抽掉主體,看動作
把每則 story 改寫成「誰對什麼做了什麼」,然後把「誰」拿掉。

> - A 公司把推論改成在使用者裝置上跑
> - B 開源專案發布了 4-bit 量化版權重
> - C 晶片商推出邊緣推論加速卡
> - D 的 API 新增了「本地快取」選項

抽掉主體之後剩下:**推論正在往端側移動**。四個不相關的組織,同一個方向。

### 2. 找跨 section 的共振
同一個 section 裡三則相似的事通常只是那個領域的常態。
**跨 section 的重複才是訊號。** 一則在 `AI_LLM`、一則在 `MACRO`、
一則在 `COMPANIES`,指向同一個底層壓力 — 那值得說。

### 3. 用 ledger 看時間軸
`find_history` 不只用來定 changeType。
某個主題如果在過去幾天反覆以不同面貌出現,那是訊號在累積。
單日的三則同向 item 可能是巧合;三天九則就不是。

在 `rationale` 裡具體寫出時間軸:「本週第三次出現同類事件」比
「近期屢見」有用得多。

---

## Signal 還是巧合

要稱得上 signal,**三個條件全部要滿足**:

1. **至少 3 則來自不相關主體的 story**。同一家公司做三件事不是趨勢,是策略。
   同一個社群的三篇貼文不是趨勢,是話題。
2. **有共同的機制,不只是共同的關鍵字**。
   三則都提到「agent」不算 — 要是三則都在解決同一個結構性問題。
3. **你能說出它的反面**。「如果這個趨勢是假的,我會看到什麼?」
   答不出來,代表這只是一句不可證偽的漂亮話,不要寫。

### 反例

| 寫法 | 為什麼不是 signal |
|---|---|
| 「AI 領域持續快速發展」 | 不可證偽,無資訊 |
| 「今天有四則跟 agent 有關的新聞」 | 關鍵字共現,不是機制 |
| 「X 公司今天發了三個產品,顯示其積極布局」 | 單一主體 |
| 「開源模型正在追趕閉源模型」 | 太泛,而且已經被說爛了 — 除非今天有新證據支持一個更具體的版本 |

### 正例

> **label**: `推論成本壓力轉向端側`
> **rationale**: 今日四則不相關事件同向:某雲端商調升推論 API 單價、
> 某開源專案釋出 4-bit 量化權重、某晶片商推邊緣加速卡、某 SDK 新增本地快取層。
> 四者分屬不同商業立場,共同反應的是同一個成本壓力。反證會是:
> 若這只是巧合,雲端推論用量與單價應在未來數週維持原趨勢。
> **storyIds**: 四則的 storyId

## 數量與寫法

- **0 到 3 條。** 多數日子是 0 或 1。逼自己每天生出三條的結果一定是灌水。
- 沒有夠格的就交空陣列。空陣列是合法且誠實的答案。
- `label`:一個名詞短語,6–15 字。像小標題不像句子。
- `rationale`(materials)/ `body`(brief):3–5 句。
  必須包含:哪些事件、共同機制是什麼、為什麼這不是巧合。
- `storyIds`:列出支撐這條 signal 的 storyId,全部要在 materials / brief 裡存在。

## signal 的證據不會自動變成 final story

一條 signal 的 `storyIds` 指向支撐它的 story。這些 story 必須存在於
materials / ledger,**但不代表它們每一則都要成為 brief 的 final story。**

signal 之所以成立,前提就是它的構成事件「個別看起來不起眼」 —
如果每一則都夠格獨立刊登,那它們本來就會各自被寫進去,你也不需要一條 signal
來讓讀者看見關聯。

所以:**寫了 signal,就不要再把它的弱證據一則一則也寫成 final story。**
否則同一份情報價值在簡報裡被算兩次,版面被稀釋,其他真正獨立的 story 被擠掉。

每一則構成事件都要通過 `editorial-policy.md` 的 **Standalone Value Test**:

> 如果這條 aggregate signal 不存在,這則事件還值得佔一個 story 位置嗎?

- 不值得 → 只留在 `storyIds` 裡當證據。
- 值得 → 才可以同時獨立刊登。

一條由四則構成的 signal,典型結果是 0 到 1 則構成事件另外獨立成篇,
而不是四則全上。

## 與 dailyAnalysis 的分工

- `emergingSignals`:跨日、跨領域的**結構性**觀察。
- `dailyAnalysis`:今天這批 story 之間的**當日**關聯與判斷。

同一個論點不要在兩邊各寫一次。
