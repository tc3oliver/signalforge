## Reports — point-in-time, not maintained

Each of these is evidence from a specific date. They are deliberately *not*
updated as the system moves on: rewriting them would destroy the record of what
was actually true when the measurement was taken. Read them as history, and
check any claim against the reference documents above before acting on it.

| Report | Date | What it records |
|---|---|---|
| [`reports/PHASE1_REPORT.md`](reports/PHASE1_REPORT.md) | 2026-09-13 | The prototype's measured results and known limitations |
| [`reports/STABILITY_REPORT.md`](reports/STABILITY_REPORT.md) | 2026-09-13 | Cross-lineage agreement against the 0.85 gate. Generated by `pnpm stability:run` — do not edit by hand |
| [`reports/LIVE_RUN_REPORT.md`](reports/LIVE_RUN_REPORT.md) | 2026-09-13 | The first end-to-end production run. Partly superseded by the connector report |
| [`reports/CONNECTOR_ENABLEMENT_REPORT.md`](reports/CONNECTOR_ENABLEMENT_REPORT.md) | 2026-09-13 | The run made after credentials were supplied |
| [`reports/FINAL_ACCEPTANCE_REPORT.md`](reports/FINAL_ACCEPTANCE_REPORT.md) | 2026-09-13 | Acceptance criteria, one row each |
| [`reports/QUALITY_REVIEW.md`](reports/QUALITY_REVIEW.md) | 2026-09-13 | Critical product and engineering assessment, defects D1–D23, priorities P0–P2 |
| [`reports/P0_FIX_REPORT.md`](reports/P0_FIX_REPORT.md) | 2026-09-13 | Root cause, change, regression test and before/after for each P0 defect |

`reports/stability.json` is the machine-readable form of the stability report and
is regenerated alongside it.
